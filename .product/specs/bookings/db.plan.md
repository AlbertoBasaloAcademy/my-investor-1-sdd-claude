# spec - bookings - db

## Specification

The `db` container must persist booking records with full passenger details, enforce the uniqueness constraint on `(launch_id, passenger_email)`, and retain cancelled bookings (no hard deletes). The schema is schemeless: Hibernate generates DDL from the `Booking` JPA entity defined in the `back` container.

**Context**: [spec.md](.product/specs/bookings/spec.md)
**Architecture**: [db.arch.md](.product/arch/db.arch.md)

### Data model

New table `booking` — generated by Hibernate `ddl-auto: update` from `Booking.java`.

| Column | Type | Constraints |
|--------|------|-------------|
| `id` | INTEGER | PK, auto-increment |
| `launch_id` | TEXT | NOT NULL, FK → `launch.id` |
| `passenger_name` | TEXT | NOT NULL |
| `passenger_email` | TEXT | NOT NULL |
| `passenger_phone` | TEXT | NOT NULL |
| `status` | TEXT | NOT NULL, default `'CREATED'` |

Unique constraint: `(launch_id, passenger_email)`.
